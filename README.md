# hawaii-swi-dev

[![Documentation Status](https://readthedocs.org/projects/hawaii-swi-dev/badge/?version=latest)](https://hawaii-swi-dev.readthedocs.io/en/latest/)

R&amp;D Development repo that sets up USGS Groundwater Availability model runs for modflow 6 with swi

## Setup

Install [pixi](https://pixi.sh), then from the repository root

```
pixi install
pixi run install
```

`pixi run install` installs the latest MODFLOW 6 release from
[modflow6-feat-swi-preview](https://github.com/jdhughes-dev/modflow6-feat-swi-preview)
(linux, macOS on Apple silicon, and Windows) into the pixi environment using
`get-modflow` from the develop branch of flopy. The release DFN files are
extracted to `dfn/` and the flopy MODFLOW 6 classes are regenerated from them,
so flopy supports the SWI package. The first `pixi run` or `pixi shell` does the
same automatically if it has not been done.

Run `pixi run get-mf6` to update to a newer preview release, or
`pixi run get-mf6 --force` to reinstall. `pixi run check-mf6` reports the
installed version and `pixi run smoke-test` builds and runs a small SWI model.

## USGS data release

`pixi run get-data` downloads the MODFLOW-2005 SWI2 models of Kauai, Oahu, and
Maui from Rotzoll and Izuka (2023,
[doi:10.5066/P97CPK5C](https://doi.org/10.5066/P97CPK5C)) to `data/pp1876/`,
which is excluded from the repository. Pass island names to extract only those
models, for example `pixi run get-data oahu`. Files are downloaded only when
they are missing locally or their checksum on ScienceBase has changed; pass
`--force` to download them again. The release includes the model input and the
MODFLOW-2005 output, so the original models do not have to be rerun. To rerun
them, `pixi run get-exes` installs the mixed (`mf2005`) and double
(`mf2005dbl`) precision MODFLOW-2005 executables; the release output was
generated with mixed precision MODFLOW-2005 version 1.12.00.

## Model output

Model output is always written to an `output/` directory beside the model input
files, for example

```
models/oahu/
    mfsim.nam
    oahu.dis
    ...
    output/
        oahu.hds
        oahu.cbc
        oahu.zta
```

Set the output file names in flopy with the `output/` prefix (e.g.
`head_filerecord="output/oahu.hds"`) and create the directory before running
mf6, which does not create it. `output/` directories and MODFLOW 6 output files
(`*.hds`, `*.cbc`, `*.grb`, `*.lst`, etc.) are excluded from the repository.

## Notebooks

The notebooks in `notebooks/` and `notebooks-verification/` are jupytext
percent-format `.py` files, which are the tracked source. Each is paired with a
`.ipynb` of the same name (`jupytext.toml`), which is not tracked; opening and
saving either file in JupyterLab updates both, and `pixi run sync-notebooks`
creates or updates the `.ipynb` files.

## SWI test notebooks

`notebooks-verification/` holds jupytext notebooks that build, run, and plot the SWI Package
tests, ported from the autotests on the `feat-swi` branch of
[christianlangevin/modflow6](https://github.com/christianlangevin/modflow6/tree/feat-swi).
Each notebook checks its results against the test's criteria and fails if they
are not met. Open them in JupyterLab (`pixi run jupyter`) or run all of them
with

```
pixi run run-verification-notebooks
```

which fails on an error or a notebook that takes longer than 30 s. The model
files are generated by flopy in `notebooks-verification/models/`, which is
excluded from the repository.

`pixi run docs-build-exec` executes the notebooks and builds the documentation
in `docs/_build/html` (`pixi run docs-build` renders them without output). The
docs workflow does the same, uploads the executed notebooks as an artifact, and
triggers a Read the Docs build, which downloads and renders them without
running MODFLOW 6. Read the Docs needs a `GITHUB_TOKEN` environment variable to
download the artifact, and the repository needs `RTDS_WEBHOOK_URL` and
`RTDS_WEBHOOK_TOKEN` secrets from the Read the Docs project's webhook.
